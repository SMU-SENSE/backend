# AAC 카드 추천 백엔드 연동 명세 (초안)

> 백엔드 실제 구현(경로·필드 이름·스키마)과 이 명세의 차이는 `docs/progress_yji.md`의 "명세와 다른 점"을 본다.

작성일: 2026-11-11 (2026-11-12 모델 빌드 결과 반영)

추천 모델은 `model.json` 파일 하나로 전달됩니다. 다음 카드를 추천하는 계산은 앱에서 합니다. 백엔드가 맡을 일은 아래 다섯 가지입니다.

- 카드 DB
- 커스텀 카드
- 사용 기록 저장
- `model.json` 배포
- LLM 문장 생성 중계

API 경로와 필드 이름은 제안이므로, 백엔드 사정에 맞게 바꿔도 됩니다.

## 1. 구성

```
[모델 빌드 (PC, Python)] ── model.json ──▶ [백엔드] ── model.json, 카드 목록 ──▶ [앱]
                                              ▲   │
                         사용 기록 (선택한 카드 순서) │   │ 프롬프트
                                              │   ▼
                         [앱] ── 카드 ID 순서 ──▶ [백엔드] ──▶ [LLM] ──▶ 완성 문장
```

| 구성 요소 | 하는 일 |
| --- | --- |
| 모델 빌드 | 말뭉치로 카드 n-gram을 학습해서 `model.json`을 만듭니다. 기본 카드가 바뀔 때만 다시 실행합니다 |
| 백엔드 | 카드 DB, 커스텀 카드, 사용 기록을 저장하고, 모델 파일을 배포하고, LLM 호출을 중계합니다 |
| 앱 | 다음 카드 추천 점수를 계산합니다(5장). 오프라인에서도 동작해야 합니다 |
| LLM | 카드 순서를 자연스러운 문장으로 바꿉니다. 예: `[밥] [먹다] [싫어요]` → "밥 먹기 싫어요" |

## 2. 카드 DB

### categories

| 컬럼 | 타입 | 설명 |
| --- | --- | --- |
| category | string, PK | 영문 코드. 아래 표 참고 |
| name | string | 화면에 보이는 이름 (예: 음식) |
| color | string | HEX 색상 |

| category | name | color |
| --- | --- | --- |
| emergency | 긴급어 | #FF8587 |
| people | 사람 | #FFB185 |
| food | 음식 | #FFDE85 |
| place | 장소 | #FFDE85 |
| body | 신체 | #FFDE85 |
| action | 행동 | #93F1CD |
| emotion | 감정 | #93DDF1 |
| describe | 설명 | #93DDF1 |
| chat | 대화 | #8593FF |
| grammar | 문법 | #BDC7C1 |

`emergency`, `food`, `chat`은 Figma 이름 규칙의 예시(`ic_emergency_help`, `ic_food_water`, `ic_chat_yes`)를 따랐습니다. 나머지 영문 코드는 제안입니다.

현재 모델 빌드에 쓴 카드 목록은 101장(추천 대상 95장, 긴급어 6장)입니다. 이 목록의 `card_id`는 빌드 쪽에서 임시로 붙인 값이라, Figma 레이어 이름과 맞춰서 확정해야 합니다. 확정되면 모델을 다시 빌드합니다. 문법(`grammar`) 카드는 아직 없습니다.

### cards

| 컬럼 | 타입 | 설명 |
| --- | --- | --- |
| card_id | string, PK | `ic_<category>_<name>`. Figma 레이어 이름과 같습니다. 예: `ic_food_water` |
| label | string | 화면 표시와 TTS에 쓰는 말. 예: 물 |
| category | string, FK | `categories.category` |
| predict | bool | 추천 후보에 넣을지 여부. 긴급어는 `false`입니다 |
| image | string | 상징 이미지 경로 |
| is_custom | bool | 사용자가 만든 카드인지 여부 |
| owner_id | string, null 허용 | 커스텀 카드를 만든 사용자. 기본 카드는 null |
| deleted_at | datetime, null 허용 | 삭제 시각. 삭제할 때 행을 지우지 않고 이 값만 채웁니다 |

**ID 규칙**
- `card_id`는 한번 정하면 바꾸지 않고, 다른 카드에 다시 쓰지도 않습니다. 모델과 사용 기록이 모두 이 ID를 기준으로 하기 때문입니다.
- 카드를 삭제할 때는 행을 지우지 않고 `deleted_at`만 채웁니다. 그래야 과거 사용 기록의 ID가 깨지지 않습니다.
- 형태소 매칭 패턴은 모델 빌드에서만 쓰는 정보라 백엔드에는 저장하지 않습니다.

## 3. 커스텀 카드

- `cards` 테이블에 `is_custom = true`, `owner_id = 사용자`로 저장합니다.
- `card_id`는 `ic_custom_<uuid>` 형식을 제안합니다. 사용자끼리 ID가 겹치지 않게 하기 위해서입니다.
- `category`는 반드시 기존 카테고리 중에서 고르게 합니다. 말뭉치 데이터가 없는 카드라서 카테고리 통계로 추천하기 때문입니다.
- 커스텀 카드를 추가해도 모델을 다시 만들 필요는 없습니다.

## 4. 모델 파일 (`model.json`)

```json
{
  "version": "2026.11.12-3",
  "backoff": 0.4,
  "card": {
    "":                            [["ic_people_me", 0.11672], ["ic_people_mom", 0.06005]],
    "<s>":                         [["ic_people_me", 0.15098], ["ic_people_mom", 0.07579]],
    "<s> ic_people_mom":           [["ic_people_dad", 0.18491], ["ic_action_give", 0.13518]],
    "ic_people_mom":               [["ic_people_dad", 0.18106], ["ic_action_give", 0.13953]],
    "ic_people_me ic_place_toilet": [["ic_action_go", 0.62067], ["ic_action_give", 0.30395]]
  },
  "category": {
    "":            [["people", 0.33899], ["action", 0.31961]],
    "<s>":         [["people", 0.42604], ["action", 0.24623]],
    "people":      [["action", 0.39358], ["people", 0.23976]],
    "people food": [["action", 0.74632], ["emotion", 0.16543]]
  }
}
```

위 값은 실제 `model.json`에서 일부만 가져온 것입니다. 파일에는 카드 문맥 1,611개, 카테고리 문맥 82개가 들어 있습니다.

- **키**는 바로 앞 카드 1~2개를 공백으로 이은 문자열입니다. 문장의 시작은 `<s>`라는 가짜 카드로 취급합니다.
  - `""`: 문맥 없음(1-gram)
  - `"<s>"`: 아직 아무것도 고르지 않은 상태. 문장의 첫 카드를 추천할 때 씁니다
  - `"<s> ic_people_mom"`: 첫 카드로 엄마를 고른 상태. 둘째 카드를 추천할 때 씁니다
- **값**은 `[카드 ID, 점수]` 목록입니다. 점수 순으로 정렬돼 있고, 상위 10개까지만 들어 있습니다.
  - 점수는 그 문맥 다음에 해당 카드가 나온 비율입니다. 말뭉치에서 2번 미만 나온 조합은 뺐습니다.
  - 추천 대상이 아닌 카드(`predict = false`, 긴급어)와 `emergency` 카테고리는 들어 있지 않습니다.
- **배포**: 백엔드는 버전별로 파일을 보관합니다. 앱은 `GET /api/model/latest`로 받은 `{ "version", "url" }`의 버전이 바뀌었을 때만 새 파일을 내려받고 캐시합니다.
- 파일 크기는 약 221 KB(226,272바이트)입니다. 카드가 늘면 문맥도 늘어 커질 수 있으므로, 카드 목록이 확정되면 다시 측정합니다.

## 5. 추천 점수 계산 (앱)

입력은 사용자가 지금까지 고른 카드 앞에 `<s>`를 붙인 목록의 마지막 두 개(`a`, `b`)입니다. 아직 아무것도 고르지 않았으면 목록이 `<s>` 하나뿐이라 `b = <s>`이고 `a`는 없습니다. 카드 x를 한 장 골랐으면 `a = <s>`, `b = x`입니다.

1. **기본 점수**: 아래 순서로 찾아서, 후보마다 처음 찾은 점수를 씁니다. `a`가 없으면 첫 줄은 건너뜁니다.
   - `card["a b"]`
   - `card["b"]` × 0.4
   - `card[""]` × 0.16 (0.4²)

   예: 엄마 한 장을 골랐으면 `card["<s> ic_people_mom"]`, `card["ic_people_mom"]` × 0.4, `card[""]` × 0.16 순서로 찾습니다.
2. **커스텀 카드 점수**: 같은 방법으로 `category`에서 카테고리 점수를 구합니다. 그 값을 해당 카테고리의 카드 수로 나눕니다.
3. **개인 점수**: 사용자의 사용 기록으로 센 카드 n-gram에 1번과 같은 방법을 적용합니다.
4. **최종 점수**는 아래와 같습니다. `w`의 시작값은 1.0이고 설정에서 조정할 수 있습니다.

```
최종 점수 = 기본 점수 + w × 개인 점수
```

5. `predict = false`인 카드와 삭제된 카드를 빼고 상위 5개를 보여줍니다.

## 6. 사용 기록

사용자가 문장 하나를 완성할 때마다 아래 이벤트 하나를 남깁니다.

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| user_id | string | 사용자 |
| card_ids | string[] | 고른 카드 순서. 예: `["ic_food_rice", "ic_action_eat", "ic_emotion_dislike"]` |
| spoken | bool | 문장을 TTS로 실제 읽었는지 여부 |
| created_at | datetime | 기록 시각 |

- 앱은 이 기록으로 개인 n-gram 빈도를 기기 안에서 바로 갱신합니다.
- 백엔드에 원본 이벤트를 저장하면, 기기를 바꿀 때 기록을 복원할 수 있고 나중에 모델을 개선하는 데도 쓸 수 있습니다.
- 사용자의 발화 기록은 민감한 개인정보일 수 있습니다. 서버에 저장하려면 사용자 동의를 받아야 하고, 보관 기간을 정해야 합니다.

## 7. 문장 생성 API (LLM 중계)

LLM API 키는 앱에 넣지 않고 백엔드에만 둡니다.

```
POST /api/sentence
요청: { "card_ids": ["ic_food_rice", "ic_action_eat", "ic_emotion_dislike"], "style": "polite" }
응답: { "sentence": "밥 먹기 싫어요" }
```

- 백엔드는 `card_ids`를 카드 DB의 `label`로 바꿔서 LLM에 보냅니다. ID로 받기 때문에 커스텀 카드도 같은 방식으로 처리됩니다.
- `style`은 `polite`(존댓말) 또는 `casual`(반말)이고, 사용자 설정에서 가져옵니다.
- 프롬프트 규칙
  - 카드에 없는 내용을 지어내지 않습니다. 조사, 어미, 연결어만 채웁니다.
  - `[싫어요]`, `[아니]` 같은 부정 카드의 뜻을 그대로 살립니다.
  - 짧은 구어체 문장 하나만 답합니다.
- 응답이 늦거나 오류가 나면, 앱은 카드 라벨을 그대로 이어서 보여줍니다. 예: "밥 먹다 싫어요"

## 8. 미정 사항

- 앱 플랫폼
- 카드 목록과 `card_id` 최종 확정 (현재 모델은 101장 임시 목록 기준), 카테고리 영문 코드
- 문법 카드를 넣을지 여부
- 사용할 LLM과 문장 생성 API의 타임아웃
- 사용 기록을 서버에 저장할지 여부와 동의 절차
